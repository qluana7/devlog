## ✍️ 후기

지인짜 오랜만에 ABC를 치게 된거 같네요.

그동안 꽤나 바쁜 일이 있었어서 앳코더를 미뤄왔었는데, 이번에 다시 치게 되었네요.

문제로 들어가볼게요.

<p><br/></p>

앳코더의 시작은 항상 쉬운 문제였죠.

A번은 문제도 안보고 제목이랑 예제만 보고 유추해서 때려맞췄어요. 딱봐도 안봐도 부호 판별 문제였고, `a > 0 ^ b > 0`으로 간단하게 해결~

<p><br/></p>

B번은 되게 귀찮은 문제중 하나죠

예제를 보고 직관적으로 x가 한줄로 나열되게 된 위치를 구하는 문제지만.. 가로, 세로를 둘다 생각해야한다는 점이 있죠.

구현은 의외로 간단하게 풀 수 있는데, 문자열 입력을 받으면서, 세로 누적합과 가로 누적합을 저장해주면 되요.

'o'를 기준으로 합산했다면, 합산 결과가 0인 부분이 x로 이루어진 행 또는 열이 될거에요.

<p><br/></p>

C번은 문제가 되게 특이했는데, 문제를 간단하게 요약하자면 다음과 같아요.

// 1-base index
i = 1 -> n, j = 1 -> n (i != j)에 대해, $C_i \noteq C_j$를 만족하는 `min(i, j)`를 구하면 되요.

문제를 계속 살펴보다가 재미난 관찰을 하였는데, 연속된 같은 숫자를 하나의 그룹으로 생각한다 했을 때, 맨 앞 그룹과 맨 뒷 그룹을 제외한 나머지 그룹은, 중앙을 기준으로 1에서 시작해 1로 끝나는 바이토닉 수열이 구성되면 되요

가령, 그룹의 수가 4면, `1 2 2 1`과 같은 수열이 만들어지고, 5면 `1 2 3 2 1`과 같은 수열이 만들어지죠.

양 끝 그룹은 자신의 앞과 뒤에 다른 숫자가 없기 때문에, 증가/감소 하는 수열이 만들어질거에요.

가령, 그룹의 수가 3이면, 앞은 `3 2 1`, 뒤는 `1 2 3`.

이런식으로 그룹마다 위 수열을 출력해주면 간단하게 풀 수 있어요.

<p><br/></p>

다음은.. 할말이 많은 D인데...

C를 20분만에 풀어내면서 널널한 시간을 가지고 문제에 접근했어요.

제가 문자열에 조금 약하다는 생각을 평소에도 가지고 있는데, D번을 보니 문자열인거에요. 근데 어쩌겠어요. 일단 풀어봐야죠.

문제는 간단했어요, 임의의 i, j (i < j)에 대해, non-empty string으로 3분할 했을 때, 각 그룹에 A, B, C가 각각 1개 이상씩 포함되도록 하는 분할법의 갯수를 구하라는거였죠.

문제를 보고 고민하다가 의외로 빠르게 아이디어가 잡혀갔어요.

경우의 수를 셀 때, 결국 앞부분과 뒷부분에 대해 만족하는 최소를 구하면, 가운데 그룹에 대해서만 개수를 세면 되지 않을까? 라는거였죠.

앞과 뒷그룹을 최소로 분리했을 때, 가운데 그룹에서 만족하는 구간의 갯수만 구한다면, 남은 부분은 자연스럽게 앞그룹과 뒷그룹에게 넘겨버리면 되니깐요.

그리고 가운데 그룹을 어떻게 할까 하다가.. 고민 끝에 투포인터로 처리하기로 했어요.

l, r을 잡고, r을 밀어가며 만족할때까지 이동하고, 만족하는 구간에 대해, 결과에 (n - r + 1)을 더해줘요.

n - r + 1을 더하는 이유는, 구해진 (l, r)이 최소 구간이기 때문에, 남은 문자열을 포함시키는 경우와 아닌 경우를 합산하기 위함이에요.

구간이 조건을 만족하지 않을 때까지 l을 밀어주면서 (n - r + 1)을 더해주어 경우의 수를 구해가요.

최종적으로 합산 결과가 최종 답이 될거에요.

사실, D는 무려 4번이나 틀려먹었는데...

처음 2번은 구현을 잘못한 곳이 있어서 틀렸는데, 그 뒤로 혹시나 하는 마음의 결과 자료형을 i64로 바꾼 순간... 테케 1개 빼고 전부 맞더라고요.

여기서 문제가 발생했는데.. 그냥 아무 생각 없이 어? 한개? u64로 바꿔볼까? 하고 패널티 무시하고 제출했던게 너무 뼈아픈 실수였어요.

최종적으로 로직에서 틀린 부분을 수정해주고 제출했더니, AC! 이때가 약 1시간 13분 지났으니, 대략 27분 정도 남은 셈이에요.

<p><br/></p>

E번은 문제 자체는 너무나도 간단해보였어요.

단순히 기존 shortest path에 색깔 조건을 추가한게 다였죠.

시간도 얼마 안남았고, 혹시나 하는 마음에 지문 그대로 구현해서 제출해봤지만.. TLE와 MLE만 무더기로 떨어졌죠.

어찌저찌 TLE는 해결했지만, 당연하게도 정해가 아니니, MLE가 났고, 그렇게 대회가 끝났죠.

대회가 끝나고, E번의 아이디어가 너무 궁금해 solved.ac를 통해 물어봤어요. 그랬더니, 너무나도 간단하면서도 기가막한 아이디어가 나왔어요.

한 정점에 방문할 때, 서로 다른 2가지의 색으로 방문했다면, 그 정점은 더 방문할 필요가 없다. 였죠.

곰곰이 생각해보니깐 그랬어요. 2가지 다른 색으로 정점에 방문하면, 기존 방문 때 체크하지 못했던 같은 색 경로도 커버가 되니깐, 그 이상의 색깔에 대해 생각할 필요가 없던거에요.

이런 아이디어를 즉시 코드에 적용해서 visited를 수정하고 제출해봤는데...

TLE도 안나고, MLE도 안나는 빠른 코드로 AC가 나서, E번 업솔빙까지 마치게 되었죠.

사실 오랫동안 안해가지고 못풀면 어떡하지 라는 걱정으로 했었는데, 문제 아이디어 자체는 의외로 금방금방 떠올렸떤거 같아요.
